# Testing Rules

- Add or update tests when changing business logic, validation, authentication, database behavior, or reusable components.
- Test user-visible behavior instead of implementation details.
- Include successful and failur cases when appropriate.
- Test required-field and invalid-input behavior for forms.
- Test loading, empty, and error states for data-driven components.
- Do not remove existing tests to make a change pass.
- Keep tests independent and repeatable.
